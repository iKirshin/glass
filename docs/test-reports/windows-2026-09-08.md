### Cause (verified on the machine)

Python is genuinely absent, not merely unconfigured:

- `C:\Users\<user>\AppData\Local\Programs\Python\` — does not exist.
- `C:\Program Files\Python311\python.exe` — does not exist.
- The only `python` / `python3` on `PATH` are the Microsoft Store alias stubs in
  `%LOCALAPPDATA%\Microsoft\WindowsApps`. These exit immediately without printing a
  version, which is exactly why node-gyp reports `version is ""` →
  `THIS VERSION OF PYTHON IS NOT SUPPORTED` for every candidate it probes.

This is an environment gap on the test machine, not a defect in the branch.

### Not yet established

node-gyp aborted during the Python search, before it probed for a C++ toolchain, so it is
unknown whether the native build would also fail on MSVC. Relevant state:
`C:\Program Files\Microsoft Visual Studio\` does not exist;
`C:\Program Files (x86)\Microsoft Visual Studio\` contains only `2019` and `Shared`, with
no `Installer\vswhere.exe`. Expect a second failure on the C++ toolchain after Python is
installed, and budget for it.

### Secondary observation

Before the hard failure, npm could not clean up its staging directory:

```
npm warn cleanup Failed to remove some directories [
npm warn cleanup     '\\?\C:\Users\<user>\InPro\node_modules\keytar',
npm warn cleanup     [Error: EBUSY: resource busy or locked, rmdir '...\node_modules\keytar']
```

`keytar` was locked by another process during the install. Worth clearing before the
retry — a stale Electron or node process holding `keytar.node` can make a subsequent
install fail for an unrelated reason and confuse the diagnosis.

## 4. To unblock

1. Install CPython 3.x proper (not the Store stub) and make sure `py -3 --version` works,
   or point node-gyp at it explicitly (`npm config set python "C:\Path\To\python.exe"`).
2. Install the "Desktop development with C++" workload (VS Build Tools) if the toolchain
   probe then fails.
3. Ensure no process is holding `node_modules\keytar`, delete `node_modules`, and rerun
   `npm install`.
4. Rerun this plan from step 2.

## 5. Note on the plan itself

Step 2 of `docs/windows-testing.md` says `npm install` "must rebuild better-sqlite3,
keytar, sharp for Electron 44 without compiler errors" but does not list the native build
prerequisites. Adding Python 3 and the MSVC C++ workload to the plan as preconditions —
checked before the run starts — would have caught this in seconds instead of after a full
dependency download.

Also: the startup log the plan asks for lands under `docs/test-reports/` but is caught by
the blanket `*.log` rule at `.gitignore:4`, so it can only be committed with `git add -f`.
A negation rule (`!docs/test-reports/*.log`) would make step 2 work without the override.
